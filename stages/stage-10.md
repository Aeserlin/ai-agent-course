## 阶段导读

技术学完不等于能拿到 offer。这一阶段解决三个具体问题：**知识是散的，串不起来**；**项目做过但讲不清**；**简历投出去没有回音**。目标是让你在 3 分钟内讲清一个项目，在 30 秒内答清一个技术点，在简历上写出让面试官想追问的句子。

先看清面试在考什么。初级岗位考三样：**基础是否扎实**（语言、数据库、网络）、**项目是否真做过**（细节、取舍、踩坑）、**能不能沟通**（表达是否有结构、是否听得懂问题）。AI 岗位再加一层：你是否理解模型的能力边界，知道什么时候该用 RAG、什么时候该上 Agent、什么时候老老实实写规则。

这一阶段的产出很具体：一张能手绘的知识地图、三个能讲透的主项目、一份一页纸简历、一套至少 100 题的题库、若干次模拟面试录音。这些东西不是“准备好了再开始”，而是边整理边发现漏洞——你会在讲项目时发现某个环节其实没搞懂，这恰恰是最有价值的复习信号。

最容易踩的坑有五个。**背题不理解**，换个问法就露馅；**项目讲成流水账**，“我用了 SpringBoot、Redis、LangGraph”，没有问题和取舍；**简历堆名词**，写二十个框架，一问深度就崩；**虚构项目**，面试官深挖三层就问穿；**只准备技术不准备表达**，明明会做，讲得磕磕巴巴。

<div class="callout plain"><span class="tag">大白话</span>
<p>面试不是考试，是<b>一次技术相亲</b>。</p>
<p>面试官在判断三件事：你能不能干活、好不好合作、有没有潜力。所以“我学过什么”不重要，<b>“我解决过什么问题、怎么想的、结果如何”</b>才重要。</p>
<p>把项目讲成故事，把技术讲成选择，把失败讲成经验，你就赢了一半。</p>
</div>

## 学习前准备

### 前置知识

| 能力 | 最低要求 | 不达标会怎样 |
|-|-|-|
| 项目经历 | 至少完整做过 2 个项目并部署过 | 没有素材可讲，只能背题 |
| 技术基础 | 语言、数据库、网络、框架有基本理解 | 深挖一层就答不上 |
| 表达 | 能把一件事按“背景—行动—结果”说清 | 面试官听不出你的贡献 |
| 写作 | 能写结构化文档 | 简历像流水账 |
| 自我认知 | 知道自己想做什么方向 | 职业规划答得像背模板 |

### 材料与工具清单

| 材料 | 用途 |
|-|-|
| 项目代码与部署地址 | 面试现场演示或复盘细节 |
| 架构图（手绘或 draw.io） | 讲项目时同步画 |
| 一页简历（PDF + Word 源文件） | 投递与现场修改 |
| 题库（Excel / Notion / Markdown） | 按掌握度复习 |
| 录音设备（手机即可） | 模拟面试复盘 |
| 目标岗位 JD 10 份 | 做关键词匹配与方向校准 |
| 投递记录表 | 记录公司、岗位、进度、反馈 |

### 三道自测题

| 题目 | 参考答案要点 |
|-|-|
| 1. 用 3 分钟讲你最强的项目，第一句话说什么？ | 先说业务问题与结果，例如“客服每天重复回答 300 次同类问题，我做了一套 RAG 问答，把人工转接率降了 40%”，再展开技术。不要从“我用了什么框架”开始。 |
| 2. 面试官问“这个项目你负责哪部分”，怎么答才不失分？ | 明确边界：我负责检索链路与评测，另外两位同学负责前端与部署；再说我做的具体决策与带来的指标变化。既不夸大也不模糊。 |
| 3. 简历上写“优化了 RAG 检索”，面试官会追问什么？ | 会追问：优化前指标多少、用了什么手段、为什么选这个手段、如何评测、有没有副作用。写不出这五点，就不要写这句话。 |

## 模块精讲

### 模块1：就业面试题讲解（技术串讲与模拟考试）

#### 解决什么问题

学了五个多月，知识点是散的：Python 的装饰器、MySQL 的索引、LangGraph 的状态、RAG 的重排，各自都懂一点，但被问“它们怎么串起来”就卡住。这一模块要解决的是**把碎片整理成体系，并能按面试官的节奏取用**。

#### 核心概念

| 概念 | 含义 | 用法 |
|-|-|-|
| 知识地图 | 三级结构：阶段 → 模块 → 关键点 | 先看全局，再补局部 |
| 四问法 | 是什么 / 为什么 / 怎么做 / 踩过什么坑 | 每个技术点都过一遍 |
| 项目串讲 | 背景、目标、架构、我的职责、难点、结果 | 控制在 3 分钟 |
| 模拟考试 | 限时、随机、口述 | 训练临场提取能力 |
| 掌握度分级 | 会背 / 会用 / 能讲清取舍 | 按级别分配复习时间 |
| 追问链 | 每个答案准备下一层 | 防止被问到第三层就崩 |

四问法是最小复习单元。以“Redis 缓存”为例：是什么（内存键值库）；为什么用（降低数据库压力、提升响应）；怎么做（缓存穿透用空值或布隆过滤器，击穿用互斥锁，雪崩加随机过期）；踩过什么坑（大 key 阻塞、缓存与数据库不一致）。四问答完，才算真的会。

知识地图不要抄目录，要按“你能否复述”来画。画不出来的分支，就是你的漏洞。

#### 关键实现

把题库做成结构化数据，按掌握度安排复习，而不是每次从第一页开始刷：

```python
# review/plan.py
import json
from collections import defaultdict

# 题库：dir 方向，level 难度 1-3，mastered 掌握度 0-3
questions = [
    {"dir": "Python", "q": "装饰器的本质是什么", "level": 1, "mastered": 3},
    {"dir": "MySQL", "q": "什么情况下索引会失效", "level": 2, "mastered": 2},
    {"dir": "Agent", "q": "ReAct 的循环由哪几步组成", "level": 2, "mastered": 1},
    {"dir": "RAG", "q": "混合检索为什么比纯向量更好", "level": 3, "mastered": 0},
    {"dir": "工程化", "q": "SSE 部署到 Nginx 后为什么变成一次性返回", "level": 3, "mastered": 1},
]

def daily_plan(items: list[dict], limit: int = 12) -> list[dict]:
    """优先复习“高难度 + 低掌握”，同方向穿插，避免疲劳"""
    picked = sorted(items, key=lambda i: (i["mastered"], -i["level"]))
    return picked[:limit]

def stats(items: list[dict]) -> dict:
    """按方向统计掌握率，找出最弱的方向"""
    agg = defaultdict(lambda: [0, 0])
    for i in items:
        agg[i["dir"]][0] += i["mastered"]
        agg[i["dir"]][1] += 3
    return {d: f"{v[0] / v[1]:.0%}" for d, v in agg.items()}

print("今日计划：", [q["q"] for q in daily_plan(questions)])
print("方向掌握率：", stats(questions))
```

项目串讲用固定模板，避免每次讲得不一样：

```text
【背景】客服团队每天 800 段对话，人工只能抽查 20 段，合规风险发现滞后。
【目标】自动质检，高危工单 10 秒内推给组长。
【架构】Dify 工作流做意图与合规判断 → 代码节点算风险分 → 钉钉推送；
        外层用 FastAPI 代理，负责鉴权、限流与日志。
【我的职责】工作流设计、合规规则、风险分算法、代理层与监控。
【难点】模型输出不稳定，经常少字段。做法是 JSON 模式 + 代码校验 + 失败重试一次，
        仍失败则降级为“需人工复核”，不阻塞主流程。
【结果】100 段标注样本分类准确率 87%，违规召回 100%，P95 耗时 6 秒。
```

#### 代码解析

| 片段 | 作用 | 为什么这样写 |
|-|-|-|
| `mastered` 0–3 | 量化掌握度 | 凭感觉复习会一直刷会的题 |
| 排序键 `(mastered, -level)` | 先补弱项难题 | 时间要花在不会且重要的地方 |
| 按方向统计 | 发现系统性短板 | 某个方向整体弱，要回到项目补 |
| 固定串讲模板 | 保证表达稳定 | 紧张时也能按结构说完 |
| 结果带指标 | 让表达可信 | 没有数字的“效果不错”等于没说 |
| 难点讲失败与兜底 | 展示工程思维 | 面试官更信“踩过坑并解决” | 

#### 常见坑

<div class="callout warn"><span class="tag">易错点</span>
<ul>
<li><b>只背答案不理解</b>：换个问法就崩。每个答案准备“为什么”和“反例”。</li>
<li><b>项目讲成技术清单</b>：面试官听不出你解决了什么问题。先讲业务与结果。</li>
<li><b>把团队成果说成个人</b>：追问细节立刻露馅。明确边界，讲自己做的决策。</li>
<li><b>不准备追问链</b>：第一层答得漂亮，第二层就“没深入了解”。每个答案多准备两层。</li>
<li><b>只复习会的</b>：舒适区刷题，考场还是不会。按掌握度排序。</li>
<li><b>忽略软技能</b>：表达混乱、打断别人、答非所问，技术再好也会被拒。</li>
</ul>
</div>

### 模块2：就业简历指导（简历、规划与模拟面试）

#### 解决什么问题

简历的作用不是“记录你学过什么”，而是**在 15 秒内让面试官判断“值得聊一聊”**。同时，转行学员常被问“你为什么转行、想做什么方向”，答不好会被认为没有规划。这一模块解决“写什么、怎么写、怎么投、怎么答规划”。

#### 核心概念

| 概念 | 含义 | 做法 |
|-|-|-|
| 一页纸 | 应届与转行控制在 1 页 | 只留最相关、最能讲透的 |
| 量化 | 用数字替代形容词 | 准确率、延迟、成本、提升比例 |
| 关键词匹配 | 对齐目标 JD | 从 10 份 JD 提取高频词 |
| 可追问性 | 每句话都能扛三层深挖 | 写不出来的内容直接删 |
| 结构 | 基本信息 / 技能 / 项目 / 教育 / 其他 | 项目放最显眼位置 |
| 职业规划 | 方向 + 节奏 + 与岗位的匹配 | 具体到岗位与技术栈，不空谈 |
| 线上简历 | 超级简历、飞书文档、个人站 | 注意导出 PDF 的排版兼容 |

简历的项目描述用“问题—动作—结果”三句，不要写成功能列表。功能列表（“实现了登录、下单、支付”）任何人都能写；问题与结果才能体现你的价值。

#### 关键实现

一页纸的结构可以照下面排版：

```text
姓名 | 求职意向：AI 应用开发 | 电话 | 邮箱 | GitHub

【专业技能】
- 语言：Python（熟练）、Java（熟悉）、SQL
- AI：LangChain / LangGraph、RAG（混合检索 + 重排）、Prompt 工程、LoRA 微调
- 后端：FastAPI、SpringBoot3、MySQL、Redis、Docker、Nginx

【项目经历】
项目一：企业客服质检系统（2026.09–2026.10）
- 背景：客服日均 800 段对话，人工抽检覆盖率不足 3%。
- 我的工作：设计 Dify 工作流与合规规则，实现风险分算法与钉钉告警；
  外层 FastAPI 代理负责鉴权、限流与日志。
- 结果：分类准确率 87%，违规召回 100%，高危工单 10 秒内触达，P95 6 秒。

项目二：多智能体舆情分析平台（2026.08–2026.09）
- 背景：品牌负面信息平均滞后一天才发现。
- 我的工作：Redis 队列分布式采集、BERT + 大模型融合情感研判、
  LangGraph 编排专家讨论、SSE 过程推送。
- 结果：采集重复率 < 1%，预警时延 < 5 分钟，报告 100% 结论可追溯到原文。

【教育经历】
某大学 · 某专业 · 本科（20xx–20xx）

【其他】
- 技术博客：xxx（RAG 调优系列 8 篇）
- 证书 / 开源贡献（有则写，无则删）
```

写完后用脚本做一次 JD 关键词匹配，看看简历是否“对上岗位”：

```python
# resume/match.py
import re
from collections import Counter

STOP = set("的 了 和 与 或 及 负责 熟悉 掌握 具备 优先 相关 工作 经验".split())

def keywords(text: str, top: int = 20) -> list[tuple[str, int]]:
    """极简关键词提取：中文按 2-4 字切，英文按单词；生产可用 jieba"""
    tokens = re.findall(r"[A-Za-z][A-Za-z0-9+#.]{1,}|[\u4e00-\u9fa5]{2,4}", text)
    counter = Counter(t.lower() for t in tokens if t not in STOP)
    return counter.most_common(top)

def gap(resume: str, jd: str) -> dict:
    r = {w for w, _ in keywords(resume, 60)}
    j = [w for w, _ in keywords(jd, 40)]
    missing = [w for w in j if w not in r]
    return {"jd_top": j[:15], "missing": missing[:15],
            "coverage": f"{1 - len(missing) / max(len(j), 1):.0%}"}

# 用法：把简历与目标 JD 文本粘进来
print(gap("你的简历文本", "目标岗位 JD 文本"))
```

#### 代码解析

| 片段 | 作用 | 为什么这样写 |
|-|-|-|
| 求职意向写在最前 | 快速定位 | HR 筛简历先看方向是否匹配 |
| 技能分三组 | 便于扫读 | 语言 / AI / 后端，一眼看到重点 |
| 项目用“背景—工作—结果” | 体现价值 | 功能列表没有区分度 |
| 结果带数字 | 可信 | 准确率、时延、覆盖率比“效果良好”有说服力 |
| 关键词匹配 | 对齐 JD | 很多简历死在 ATS 关键词筛选 |
| `missing` 清单 | 指导补强 | 缺的词要么补项目，要么不投这类岗位 |

#### 常见坑

<div class="callout warn"><span class="tag">易错点</span>
<ul>
<li><b>写二十个技术名词</b>：面试官随便挑一个深挖就崩。只写能讲透的。</li>
<li><b>项目没有数字</b>：全是“优化了”“提升了”，无法判断真假。</li>
<li><b>虚构项目</b>：深挖三层必穿，还会被记录。宁可写小项目写透。</li>
<li><b>简历超过两页</b>：转行简历没人看第二页。一页足够。</li>
<li><b>一份简历投所有岗位</b>：关键词不匹配，通过率极低。按方向准备两版。</li>
<li><b>职业规划背模板</b>：“先做技术再做管理”这种答案没有信息量。要说方向与节奏。</li>
</ul>

## 综合实战

### 实战目标

把最后两周做成一个可执行的冲刺项目：**14 天从知识盘点走到模拟面试通关**。每天都有明确产出，最后形成一套可以直接用于投递的材料包。

### 第 1–3 天：知识地图与技术串讲

按 10 个阶段画一张图，每个阶段写 3–5 个关键词；再用四问法过一遍最弱的三个方向。产出：一张手绘图 + 30 条四问笔记。

### 第 4–6 天：项目盘点与表达

从做过的项目里选三个：一个全栈、一个 Agent / RAG、一个专项。每个写 3 分钟稿，画一张架构图，准备五个深挖问题（为什么这样选、失败怎么办、怎么评测、成本多少、如果重做改什么）。产出：三份项目表达包。

### 第 7–9 天：题库与模拟笔试

按方向整理 100 题，标注难度与掌握度；每天限时 30 分钟做一套自测，错题回到项目里找答案，而不是背答案。产出：题库 + 错题清单。

### 第 10–11 天：简历定稿

写一页纸初稿，做 JD 关键词匹配，删掉讲不透的句子；找一位在职工程师挑“最想追问的三句话”，逐句补细节。产出：PDF 简历 + 两版方向定制。

### 第 12–14 天：模拟面试与复盘

## 阶段项目

本阶段没有新增代码项目，产出是四份“求职材料”，按项目标准验收。

### 产出一：知识地图

**背景**：面试需要随时从大脑里取出任意一块知识，散点记忆做不到。

**产出清单**：10 个阶段的一页图；每个阶段 3–5 个关键词；标出三个最弱分支。

**技术选型 / 工具**：纸笔或 draw.io。

**验收标准**：不看资料能在 5 分钟内讲完整张图；能说清阶段之间的依赖关系。

**评分点**：完整性 40 分，层级清晰 30 分，能脱稿复述 30 分。

### 产出二：三个主项目表达包

**背景**：项目是面试的主战场，讲不清等于没做过。

**产出清单**：每个项目一份 3 分钟稿、一张架构图、五个深挖问题的答案、三条量化结果。

**技术选型 / 工具**：Markdown + draw.io + 录音。

**验收标准**：录音时长 2.5–3.5 分钟；每句话都能被追问两层；结果全部有数字。

**评分点**：结构 30 分，技术深度 30 分，真实细节 25 分，表达流畅 15 分。

### 产出三：一页纸简历

**背景**：HR 平均 15 秒看一份简历，必须一眼看到匹配度。

**产出清单**：PDF 一页；两个方向定制版；JD 关键词覆盖率报告。

**技术选型 / 工具**：Word / 超级简历 / 飞书文档。

**验收标准**：一页；每句可追问；目标 JD 关键词覆盖率不低于 70%；无错别字与格式错乱。

**评分点**：匹配度 30 分，量化 25 分，排版 20 分，真实性 25 分。

### 产出四：题库与模拟面试记录

**背景**：临场发挥不稳定，需要把表达练成肌肉记忆。

**产出清单**：100 题题库（带难度与掌握度）；三次模拟面试录音；评分表与改进清单。

**技术选型 / 工具**：Excel / Notion + 手机录音。

**验收标准**：高难度题掌握率不低于 60%；模拟面试各项均分不低于 3.5；改进项有明确复测时间。

**评分点**：题量 20 分，掌握度 30 分，模拟表现 30 分，复盘质量 20 分。

## 常见面试题

### 问题 1：请做一下自我介绍。

要点：控制在 60–90 秒。结构：一句话背景（转行前做什么）→ 为什么转 AI → 做过什么（两个项目一句话各讲结果）→ 擅长什么 → 为什么投这个岗位。不要复述简历，不要从大学讲起。

### 问题 2：为什么从原行业转做 AI 开发？

要点：给一个真实且正向的理由：看到了什么变化、做过什么尝试、验证了自己的兴趣与能力。避免“听说薪资高”。最好能接到“所以我系统学了 X，并做了 Y 项目”。

### 问题 3：讲一个你最有代表性的项目。

要点：用 STAR：背景与问题、目标、你的职责、关键难点与做法、量化结果、反思。3 分钟内讲完，主动留一个“钩子”引导面试官追问，比如“这里最难的是模型输出不稳定”。

### 问题 4：这个项目里你遇到的最大困难是什么？

要点：选一个真实的技术难点，讲清“现象—定位—尝试—最终方案—结果”。不要选“需求变更”“时间不够”这类非技术答案，也不要编一个自己没解决的困难。

### 问题 5：RAG 的检索效果不好，你会怎么优化？

要点：按链路排查：文档解析是否丢内容 → 分段是否合理 → 查询改写 → 召回方式（向量/全文/混合）→ 重排 → 上下文组装 → 提示词。每一层都要有评测指标，不能靠感觉调。

### 问题 6：什么时候该用 RAG，什么时候该微调？

要点：知识经常变、需要引用出处、数据量大且私有，用 RAG；要改变说话风格、输出格式、领域术语理解，且样本充足，用微调；两者可结合：微调模型 + RAG 知识。先问“是知识问题还是能力问题”。

### 问题 7：Agent 死循环怎么防？

要点：四道：最大轮数、最大 token 预算、重复动作检测（相同工具相同参数连续出现即中断）、明确的终止条件与人工兜底。再加可观测性，把每轮决策记下来，便于定位。

### 问题 8：工具调用失败怎么处理？

要点：区分可重试与不可重试。网络超时、限流可退避重试；参数错误要让模型修正或向用户澄清；权限错误直接失败并提示。所有失败都以结构化结果返回给模型，让它决策，而不是抛异常中断。

### 问题 9：多智能体一定比单智能体好吗？

要点：不一定。多智能体增加协调成本与不确定性，只有在任务可明确分工、需要多种专业视角、单上下文放不下时才值得。能用工作流或单 Agent 解决的，不要上多智能体。

### 问题 10：SSE 和 WebSocket 怎么选？

要点：单向推送（进度、token）用 SSE，简单、自带重连、过网关容易；双向交互（聊天、协同）用 WebSocket。部署时注意 Nginx 缓冲、超时、Upgrade 头。

### 问题 11：怎么控制大模型应用的成本？

要点：分层：小模型先筛、大模型兜底；缓存重复请求；压缩上下文、只传相关片段；限制最大输出；批量合并调用；监控 token 消耗并设预算告警。优化前先有成本基线。

### 问题 12：如何评测一个 RAG 系统？

要点：分层评测：检索层看召回率、命中率、MRR；生成层看忠实度（是否基于检索内容）、答案相关性、完整性；端到端看人工评分与业务指标。用固定评测集，每次改动都跑一遍，避免“感觉变好了”。

### 问题 13：数据库索引为什么会失效？

要点：常见原因：对列做函数或运算、隐式类型转换、前导模糊匹配 `%x`、联合索引不满足最左前缀、OR 条件部分无索引、数据区分度太低、优化器判断全表更快。用 `EXPLAIN` 验证，不要凭经验猜。

### 问题 14：你如何保证线上服务的稳定性？

要点：超时、重试、熔断、降级、限流五件套；健康检查与告警；关键链路有兜底返回；发布采用灰度与可回滚；日志与 Trace 能定位问题。再准备故障演练，验证降级真的生效。

### 问题 15：你的职业规划是什么？

要点：分近中远三段：近 1 年深耕 AI 应用开发，把 RAG 与 Agent 工程化做扎实；2–3 年能独立负责一个业务方向的方案与落地；更远希望在某个行业（如客服、医疗、电商）形成业务 + 技术的复合优势。要和应聘岗位相关，不要空谈“做管理”。

### 问题 16：你还有什么问题问我们？

要点：问三类：业务（这个岗位当前最核心的目标是什么）、团队（团队规模、分工、技术栈、评审流程）、成长（新人前三个月的期望与培养方式）。不要第一轮就问薪资与加班，也不要說“没有问题”。

## 阶段小结

- 面试考的不是“你学过什么”，而是“你解决过什么、怎么想的”。
- 知识要成体系：三级地图 + 四问法，先补弱项难题。
- 项目讲述用 STAR，结论先行，结果量化，主动暴露一个难点。
- 简历一页纸，每句都能扛住三层追问，写不出来就删。
- 职业规划要具体到方向、节奏与岗位关联，不要背模板。
- 模拟面试是性价比最高的准备方式，录音复盘能快速修正表达。
- 反问环节也是加分项，问业务、问团队、问成长。
- 投递是概率游戏，用台账管理节奏，别因一次拒信否定自己。

### 结课寄语

10 个阶段走完，你已经具备“独立交付 AI 应用”的完整能力：能从需求出发选型，能写后端与前端，能做 RAG 与 Agent，能部署上线，也能把成果讲清楚。

最后记住三句话：

1. **能用工作流解决的，不要上 Agent。** 复杂度要花在真正需要的地方。
2. **能靠架构约束的，不要只靠提示词。** 提示词会漂移，代码与流程更可靠。
3. **没有评测的优化，都是自我感觉良好。** 先有指标，再谈提升。

去投递，去面试，去被拒绝，再回来改。offer 是改出来的，不是等出来的。
